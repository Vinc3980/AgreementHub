Security model

Trust is structural, not promised.

Deny-by-default authorization, hashed credentials and sessions, append-only records, and a public verification page that reveals metadata only. Errors never leak stack traces, SQL, hashes, tokens, or audit internals.

AUDIT

Hash-chained history

Every action appends a row with a per-agreement sequence, previous hash, and event hash. Forged, edited, or deleted events are detected.

IMMUTABILITY

Final records cannot move

Database triggers freeze committed versions, signatures, final documents, and audit rows. Only drafts refresh in place.

VERIFICATION

Metadata only, by design

The public page returns category, status, version, dates, integrity, and a hash prefix. Never contents, parties, comments, or audit internals.

SIGNING

Bound to the exact version

Typed name, drawn signature, or explicit acceptance. The method and payload hash are recorded with the document hash at signing.

STORAGE

Private and hash-checked

Final PDFs live server-side under a write-once key, stream only through authenticated routes, and are re-hashed on every download.

ACCESS

Deny by default

Membership and party-role checks per agreement. Invisible resources return 404, insufficient roles return 403, and Argon2id protects passwords.

Templates

Templates are data, not code.

Each template stores a content_schema that the shared engine evaluates in the API and the web UI alike. Adding a template or category needs no UI or backend change. AI Agreement Assistant

Suggestions, never silent edits.

Five read-only assistant features: plain language to fields, missing-information review, clause explanation, summary, and suggested questions. Every response is disclaimed, nothing is written without explicit acceptance, and requests are logged with metadata only.

Describe the deal in plain language. The assistant maps suggestions onto the template’s real field codes, cites the basis for each, and lists what it could not derive instead of inventing it.
